## FastVideo 硬件适配结论：RTX 4090 + 96GB 内存（同日晚）

**结论：能跑，且有官方支持路径，但"能跑什么"分三档。**

**支持证据（都在仓库里）**
- `README.md:47` 明写 "Support H100, A100, 4090"。
- `docs/inference/optimizations.md:296` FP8 支持设备写作 "sm89+ (H100, L40S, **RTX 4090**, or newer)" —— 4090 被直接点名。
- `docs/contributing/developer_env/runpod.md:195` 把 4090 列为推荐开发卡（"Inference testing, small model fine-tuning, quick iteration"）。
- 官方基准测试用的就是 **L40S（compute_capability 8.9，48GB）** —— 与 4090 **同架构同代**，只是显存减半。所以性能可参考 L40S 数据、显存要按一半算。
- `fastvideo/tests/ssim/test_sd35_similarity.py` 与 `test_flux_t2i_similarity.py` 里有 `("RTX 4090","RTX4090")` 映射 —— 说明 CI 里有 4090 数值回归基线。**但注意：只有这两个文生图测试有 4090 基线，所有视频模型（Wan/Hunyuan/H3/LTX2…）的基线是 A40/L40S/H100/GB200/H200。**

**架构门槛（4090 = sm_89，Ada）—— 能开 / 不能开**
- ✅ FP8 权重量化（`engine.quantization.transformer_quant: FP8`）、FlashAttention 2、SageAttention 2.1.1（需源码编译）、VSA 稀疏注意力（非 Hopper 走 **Triton 内核**，见 `docs/attention/index.md`：H100 编译 TK，其他卡只装 Python+Triton）、torch.compile、DiT 逐层卸载。
- ❌ NVFP4/Attn-QAT（硬门槛 sm_120，选了会**静默回退 FA**）、SageAttention 3（要求 Blackwell/5090）、FA3/FA4（需 sm_90a，低于 sm90 被路由回 FA2）、STA（需 Hopper 且已归档）、VSA 原生 Blackwell 内核（sm_100a）。
- VSA 关键：`fastvideo-kernel/CMakeLists.txt` 中 TK(sm_90a)/FP4(sm_120a)/sm_100a 全是硬编码架构，4090 走不到；但 Triton fallback 可用。

**24GB 显存分档**
- ① 直接能跑：Wan2.1/TurboWan/FastWan 1.3B（480P）、SD3.5、FLUX.1、Z-Image。
- ② 需调优：Wan2.2 TI2V 5B（720P）、Wan2.1 14B（480P）、LTX-2、LongCat 13.6B。官方 main 里本身就有单卡 14B 480P 配置（`scripts/inference/inference_wan_VSA_DMD_14B_480P.yaml`，num_gpus: 1 + VSA_sparsity 0.9），所以 14B 单卡路径是官方承认的。
- ③ 单卡基本别想：MiniMax-H3、Wan2.2 A14B（MoE 双专家）、Hunyuan 1080P、LingBot 30B。**H3 的 SSIM 回归测试硬编码 `REQUIRED_GPUS = 4` + sp_size=4**，CUDA 示例默认 `--num-gpus 4`，性能剖面测于 4×GB200。

**96GB 内存的作用**：够用，且是 14B 档能跑的前提 —— 逐层卸载需要宿主侧持有全量权重做中转。`pin_cpu_memory` 官方在 4090 的 TurboDiffusion 例子里注释建议设 false（`basic_turbodiffusion.py:20`，未写明原因），96GB 下通常可留 true，遇 pinned 分配报错再关。

**环境硬约束（与用户本地 Mac 无关，服务器必须满足）**：Linux 或 Windows WSL（**不支持 macOS**）、Python **3.10–3.12**（3.13 会被拒）、CUDA 12.6 或 13.0、PyTorch 2.12.0。安装：`UV_TORCH_BACKEND=cu126 uv pip install fastvideo`。

**新增产出**：`fastvideo-configs/06-rtx4090-24gb-fp8-vsa.yaml`（1.3B + FP8 + VSA + 逐层卸载，稳妥档）、`07-rtx4090-24gb-14b-push.yaml`（14B 480P 压榨档）。两份均通过 YAML 解析校验。

**多卡提醒**：消费级卡无 P2P，官方文档明说"多张消费级 GPU 经慢速 PCIe 且无 P2P 时，FSDP 开销会显现"—— 加第二张 4090 能扩显存，但不一定等比例提速。

## Hypit 接入自部署模型（同日晚）—— 回答"能用自己服务器部署的模型生成视频吗"

**结论：能，且是官方文档明确列出的第一等扩展场景**（`docs/zh/guide/providers.md` 修改位置表里有「在自己的云部署上运行模型」独立一行；`service-partners.md` 明写"没有合作关系、没有官方内置 Provider，也可以使用一份合适的部署"）。

### 机制（这是核心心智）
- 三层解耦：**Model**（定义生成什么）→ **Provider**（知道如何通过某服务完成）→ **Endpoint**（配置好的实例：地址/凭据/并发）。Profile 的 `bindings` 把 capability 接到 Endpoint。
- **SVML 里写的是 capability（模型身份），不是服务商**。`<seedance:TextVideo model="mini">` → capability `@hypit/seedance@1#seedance-2-mini`。换服务 = 换 binding，**SVML 一行不改**。
- capability 全名对照：`standard`→`seedance-2`（1080p/4k, 4–15s）｜`fast`→`seedance-2-fast`（480p/720p）｜`mini`→`seedance-2-mini`（480p/720p）｜`2.5`→`seedance-2.5`（480p/720p/1080p, -1 或 4–30s）。
- Seedance 端口全集：`prompt` `duration` `resolution` `aspectRatio` `firstFrame` `lastFrame` `referenceImage` `referenceVideo` `referenceAudio` `generateAudio` `webSearch`。

### 三条路径
- **A 协议兼容直连（零代码）**：`provider-hypihub` 的 `baseUrl` 可配（默认 `https://hypit.ai/v1`，`apiBaseUrl()` 会剥掉尾部 `/v1`/`/v1beta` 再拼 `/v1`）。需实现：`GET /v1/models/{model}`→`{endpoints:["videos"]}`（**强制**，start 前必查）、`POST /v1/videos`→`{id|job_id}`、`GET /v1/jobs/{id}`→`{status}`、`GET /v1/jobs/{id}/assets`→`{items}`、`POST /v1/files/uploads`、可选 `POST /oauth/token`。状态枚举 queued/running/in_progress/succeeded/completed/failed。提交带 `idempotency-key` 头。
- **B 写项目 Provider（推荐）**：照抄 `examples/provider-package`（那个是图片版），用 `@hypit/hypit/endpoint-kit` + `/generation` + `/runtime-kit`。装法：包内 `npm run build` → 项目根 `npm install ./packages/xxx` → Profile 里 `use` 包名 + `bindings` 指过去。
- **C 自定义 Model 包**：能力差异大时才做（`model-kit` + `author-kit`）。

### 硬约束（踩过的）
1. **地址必须 HTTPS 或 localhost/127.0.0.1**。`provider-hypihub/src/activation.ts` 与官方示例都硬检查，`http://192.168.x.x` 会被拒。内网服务用 SSH 隧道：`ssh -N -L 8188:127.0.0.1:8188 user@server`。
2. **`mappingSupportsRequest` 是运行时强校验**（在 `selectWireModelForRequest` 里 assert）：请求里的每个 port 必须在 `mapping.fields` 里。所以「只声明真实支持的端口」= 不支持的请求在 plan 阶段就报错，不会静默丢。**但 `assertMappingCoversPorts` 只在 test 里调，运行时不强制** —— 所以裁剪字段是合法的。
3. **`mappingSupportsRequest` 的兜底才是 assert**，正规做法是在 capability 的 `supports()` 里先判 unsupported 并给可读原因。
4. **`@hypit/hypit@0.1.10` 的 subpath exports 里 `import` 指向 `.ts` 源码**（`types` 指 `.d.ts`）。所以 `tsc` 能过，但裸 `node` import 编译产物会报 `Stripping types is currently unsupported`。**这不是包坏了**，运行时由 Hypit Runtime 自己的解析器加载。
5. Endpoint 包 `credentials` 是**可选**的（服务无鉴权就别声明，Profile 也不用配 token）。`pricing: {kind:"local"}` 声明无 Provider 调用费用。`facet` 必需非空。
6. `doctor` 支持 `--runtime <profile>`；不指定则只查项目 Result Store，报 "Runtime Profile not selected"。

**背景**：用户问「给我远端 4090 的 IP 是不是能帮我出片」。答：能，且成片渲染**全程只吃 CPU**，4090 的唯一价值是「一台干净的 x86_64 Linux」。
