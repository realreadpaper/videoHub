## 诊断「kehu 下载慢」→ 根因是跨境丢包，开 BBR 解决（01:20–01:40）

**结论**：服务器外网带宽没问题，**慢只发生在「服务器 → 中国」这一个方向**。

- 服务器下外网实测：Cloudflare **26.5 MB/s**、GitHub 6.5 MB/s（HF 那个 401 是 gated repo 要授权，不是慢）
- 服务器 → 本机 scp：修复前 **0.11 MB/s**（200 MB 传 2 分钟只有 13 MB）
- 铁证 `ss -tnpi`（服务器侧，传输进行中抓的）：
  `rtt:158ms minrtt:104ms cwnd:2 ssthresh:2 retrans:7835，重传 11.3 MB/已发 70 MB = 16%`
  → 跨境段大量丢包 → cubic 反复 RTO → 窗口被打回 2 个 MSS → 单流 ~150 Kbps
- 修复：`modprobe tcp_bbr` + `net.ipv4.tcp_congestion_control=bbr` + 收发缓冲 208 KB → 16 MB，
  已持久化到服务器 `/etc/sysctl.d/99-net-speed.conf`
- **效果：0.11 → 6 MB/s（约 50 倍）**，200 MB 33 秒传完

**诊断口诀**：`ssh kehu 'ss -tnpi state established "( sport = :22 )"'`
看 `cwnd` 与 `retrans` —— cwnd 个位数 + retrans 上千 = 丢包型限速（开 BBR）；
cwnd 很大仍慢 = 真带宽上限（只能压文件 / 分时传）。
