## 1. 核对方法与口径

在服务器上按「服务器路径 → 本机相对路径」的固定映射生成清单
（`<相对路径>\t<md5>`），拉回本机后对同一批路径重算 md5，做集合比对：

| 类别 | 含义 | 期望 |
|---|---|---|
| md5 一致 | 逐字节相同 | 越多越好 |
| 内容不同 | 两边都有但字节不同 | 只应出现「我有意改过的文件」 |
| 漏拉 | 服务器有、本机没有 | **必须为 0** |
| 多余 | 本机有、服务器没有 | 只应出现「我新建的文档/脚本」 |

覆盖范围：`/root/s2`、`/workspace/dl`、`/workspace/trilogy`（wf_one / wf_pipeline / 全部脚本）、
`/workspace/dy_key`（wf / wf_full / 全部脚本）、`/etc/sysctl.d` + `/etc/fstab`、
`/workspace/ComfyUI/input/`（干声 / 参考帧 / 音轨切片）。

## 4. ★ 核对中发现的两个生产事实

这两条不是「拉取问题」，是核对顺带读出来的现状，但直接影响下一步怎么干：

### 4.1 373 镜全量的真实进度是 12/373，不是「已跑完」

`state/dy_key/gates_full/` 显示只有 12 个 `.done`：

```
dy1_s001 dy1_s002 dy1_s003 dy1_s004 dy1_s005 dy1_s006 dy1_s007 dy1_s008 dy1_s070
dy2_s001 dy3_s001 dy3_s100
```

即「试跑 6 镜」+ `dy1_s003–s008` 六个。**其余 361 镜从未开始。**

### 4.2 `dy1_s009` / `dy1_s010` 有 lock 残留 → 会被永久跳过

`state/dy_key/gates_full/` 下存在 `dy1_s009.lock/`、`dy1_s010.lock/` 两个**目录**
（`mkdir` 原子锁的残留）。原版 worker 的逻辑是「见到 `.lock` 就 `continue`」，
所以这 2 镜**永远领不到**，且不会报错——静默丢镜。

处置：接手旧的数据目录前先清
`find gates* -maxdepth 1 -type d -name '*.lock' -exec rmdir {} \;`

### 4.3 顺带确认：参考帧的现行版本是对的

服务器 `input/` 下同时存在三代参考帧，容易拉错：

| 目录 | 体量 | 状态 |
|---|---|---|
| `dy_full_ref/` | 373 张 / 31 M | ★ **现行版**——373 个 `wf_full` 全部引用它 |
| `dy_full_ref_v3/` | 373 张 / 67 M | 历史迭代版，**无人引用** |
| `dy_full_ref_v5/` | 6 张 / 1.1 M | 抽检样本 |

已于本机逐个解析 373 个工作流的 `LoadImage` / `LoadAudio` 节点确认：
`LoadImage` 全指向 `dy_full_ref`、`LoadAudio` 全指向 `dy_full_a`，与所拉一致。
`_v3` 那 134 MB 未拉（历史版本，无引用）。

### 5.1 权重的「可获取性」也顺手验了（不只是清单对得上）

`03_dl_weights.sh` 里每个 `dl` 调用都带**期望字节数**用于落盘校验。把它与旧机实测逐个对比，

