## 零、★★★ 剧本生产硬标准（所有剧本强制 · 不通过不得烧卡）

> **2026-09-18 用户升级为通用规范：「以后的剧本都要这么要求」。**
> 不限于本片 —— 任何新剧本、任何新片，进 manifest 之前必须先过本节。
> 扫描器：本项目 `_pipeline/review_v3.py`；通用版 `~/.workbuddy/skills/h3-film-production/scripts/review_prompts.py`。

### 0.1 四条硬标准

| 标准 | 判定口径 | 合格线 |
|---|---|---|
| **S1 零字幕** | ① 无 `<d>` 标签 ② 有 `strict_output_constraints` 段 ③ 文字道具带 `illegible abstract marks` | 三项全过 |
| **S2 表情到位** | ① 微表情 ≥3（`jaw tighten` / `muscle twitch` / `blink` / `swallow` / `lip tremble` / `eyes narrow`）② 情绪过渡 ≥1（`flickering then vanishing` / `settles into` / `cracks`）③ 完全静态词 =0（`spine straight` / `unnervingly calm` / `completely motionless` / `frozen in place`） | 三项全过 |
| **S3 位置逻辑** | ① 多人镜方位锚点 ≥1（`on the left` / `across the table` / `screen-left`）② 单人镜朝向锚点 ≥1（`facing the camera` / `facing off-screen` / `in profile` / `top-down`）③ 跨镜符合**场景空间坐标表** | 两项全过 |
| **S4 技术对齐** | ① prompt 时间戳末段 = manifest `duration` ② 工作流分辨率/帧数与 manifest **同源** | 两项全过 |

**S1 的机理**：`<d>[Chinese] "…"</d>` 是 H3 的 dialogue 结构化指令，训练数据里台词与屏幕字幕高度绑定
→ 模型把标签内中文**当画面文字渲染**。尾部自然语言禁令（`no subtitles`）优先级压不过结构化标签。
**彻底剥离比只去引号更保险**，台词只由 audio-lock 干声承载。

**S2 的机理**：H3 是音频驱动视频 —— **干声决定口型，面部肌肉与神态完全由 prompt 文字决定**。
写满"冷静/僵硬/不动"，生成出来就是木头人。正解 =「**表面 X 但内在 Y**」+ 具体微动作：

```
✗  spine straight and unnervingly calm, frozen in place
✓  shoulders squared but a muscle ticking in his jaw, a nervous swallow
   bobbing in his throat, the grin flickering then settling into grim resolve
```

### 0.2 场景空间坐标表（每个新剧本开工第一件事）

**不写进 prompt = 每镜随机摆位 = 剪辑后人物瞬移。** 每个场景（地点）开工前先建一张坐标表，
固定「机位在哪 / 谁在画面哪个方位 / 关键道具在哪」，**跨镜不得违反**：

```
场景：<地点>         机位：<正面 / 90°剖面 / 俯拍>
  S1 <角色名>   →  画面右侧近景，面向屏幕左侧
  S2 <角色名>   →  画面左侧前景，背对镜头
  道具 <名>     →  桌面正中
```

**三人及以上同框的硬要求**：90° 剖面构图 + 屏幕方位（`screen-left`/`screen-right`）+
**关系词锚定**（`mother-in-law` / `her daughter the bride`，不能只写 `mother`/`woman`）+
`Exactly three people, no extra hands`。
**禁止**「`across the table` + 主体脸朝镜头」这种几何不可能的组合 ——
实测会把配角拉到主角身边（f3s06 丈母娘"坐"到新郎边上）、主角的脸换人。

### 0.3 三关流程（缺一关不许进入下一关）

| 关 | 时机 | 做什么 | 不通过的后果 |
|---|---|---|---|
| **第一关 · 自动扫描** | 烧卡前 | `review_v3.py` 逐镜扫四条标准 | 有 FAIL → **不许烧卡** |
| **第二关 · 试拍目视** | 每片挑 1–3 镜（挑**最难**的，不是最好看的） | 抽帧看：有没有字幕 / 表情自然度 / 位置是否合理 | 有问题 → 改 prompt 重拍，**不许全量** |
| **第三关 · 复盘写回** | 出片后 | 哪镜过、哪镜什么病、归因到哪句 prompt → 写回本文件 | 不写 = 下一轮重踩 |

**自动扫描只能查「有没有写」，查不了「写得好不好」。** 表情自然度、位置是否真合理、
画面里是否真出字幕，必须第二关用眼睛看。

### 0.4 烧卡前检查清单（逐项打勾，少一项不许点火）

1. [ ] 全部镜 prompt 四条标准全过（`review_v3.py` 无 FAIL）
2. [ ] manifest / 工作流 / prompt 三者时长一致（prompt 末段 = `duration`）
3. [ ] 干声按 `duration` 生成（不是 trim 值），采样率/声道与远端 audio VAE 对齐
4. [ ] 每镜方位描述符合场景坐标表；三人同框镜有三人约束
5. [ ] 队列为空（`curl /queue` → `queue_running` = 0）且显存已 `POST /free`
6. [ ] 试拍镜已挑好（最难的那几个），断点续跑 gate 就绪

## 一、生产 SOP（不可跳过）

```
⓪ 剧本定稿 → 建场景空间坐标表 → 过四条硬标准（见 §零）
① 开拍前：剧本 → 分镜确认表 → 爸爸确认 → 才生成 manifest
② 烧卡前：挑 2–3 个代表性镜头试拍（对话镜 / 产品·道具镜 / 情感转折镜）
           → 看成片没问题 → 才跑全量
③ 出片后：视频 + manifest → 复盘报告（哪镜过、哪镜什么病、归因到哪句提示词）
           → 修复 → 只重生成失败镜，不整片重跑
④ 复盘教训写回本文件
```

**第①步的判据**：分镜确认表里每一镜必须能回答"这镜要观众看到什么、情绪到哪、几秒够不够"。
答不上来的镜不许进 manifest。

**第②步的判据**：试拍镜必须挑**最难**的，不是最好看的。挑简单的试拍等于自欺。

**第③步的收益**：24 镜全量 ≈ 52 分钟机时；只重跑 3 镜 ≈ 6 分钟。**不整片重跑是硬规矩。**

## 二、★ 时长栅格（排期唯一权威）

H3 `length` ∈ **17n+5**（min 5 / step 17 / 向上吸附），之后 LTX `frame_policy`
默认 **`trim_to_8n_plus_1`**（只裁不补、向下取 8m+1）。

→ **成片时长 = trim(H3 帧)，不等于 H3 帧。**

| H3 帧 | 成片秒 | 裁掉 | 备注 |
|---|---|---|---|
| 243 | 10.042 | 2 | 低于本片地板，不用 |
| 260 | 10.708 | 3 | 低于地板 |
| 277 | 11.375 | 4 | **地板** |
| 294 | 12.042 | 5 | |
| 311 | 12.708 | 6 | |
| 328 | 13.375 | 7 | |
| **345** | **14.375** | **0** | ★ 唯一双对齐无损 |
| 362 | 15.042 | 1 | 满窗 |

- **禁止填任意秒数**：写 13.0 → 吸附 328 → 裁 321 → 实际 13.375s，**字幕轴全错**且静默发生。
- 改排期只能改 `_后期/retime_shots.py` 的 `PLAN` 表，值必须是 `17n+5`。
- 写回前 `audit()` 硬校验四项：**栅格归属 / 裁后帧一致 / 时长在带内 / 时间戳递增且末段覆盖全长**。
  任一不过 → `exit 2`，**一个字都不写**。

## 三、★ 流水线必须两段分离（第①点，写死不是建议）

- H3 权重 20.97 GB、LTX-2.5 22B 权重 20.03 GB，**逐镜交替 = 每镜装卸一次约 20 GB**。
- 实测：批处理 149 s/镜 vs 逐镜交替 248 s/镜 → 24 镜多付约 40 分钟，全是搬运，一帧没多出来。
- 规矩：`_pipeline/run_server.sh` 里阶段 A 全部跑完 → **`POST /free` 强制释放** → 才进阶段 B。
- 完成状态落盘 `gates/<key>.s1.done` / `.s2.done`，崩了只补失败镜。
- **两阶段比一步直出 768 快 3.7 倍**（0.96 h vs 3.56 h，同 20 镜）——不只是质量选择，也是成本选择。

## 四、★ 禁字三层防线

1. **拆互斥**（最易漏）：prompt 里一边说"画一张写着 X 的纸"、一边写 `no on-screen text`
   → 模型只能产出半生不熟的伪汉字，**比纯乱码更难看**。
   本轮 7 处已降级为"只可辨性质、不可辨内容"：

   | 片·镜 | 原文 | 改成 |
   |---|---|---|
   | 1·1 / 1·2 | `rose ... reading Groom` | 删 `reading Groom` |
   | 1·2 | `paper slip reading thirty-eight thousand eight hundred` | `illegible abstract marks, no readable characters or digits` |
   | 2·2 | `brush calligraphy reading twenty thousand` | `brush strokes ... illegible abstract ink marks` |
   | 3·1 / 3·2 | `printed legal ... agreement` | 去 `printed` |
   | 3·4 | `handwritten debt notices` | 加 `every stroke rendering as illegible` |
   | 3·5 | `loan figure: "1,200,000 RMB"` | `ink strokes ... every character and digit illegible` |

2. **独立强制段**：每镜 prompt 末尾必须有 `strict_output_constraints:` 段，
   由 `_pipeline/patch_notext.py` 注入（幂等），**不手写**，避免 24 份参差。
3. **产物目视**：`_后期/scan_text_band.py` 扫字幕带。
   ⚠ OCR 认不出 H3 伪汉字，**不可靠**，只能当辅助。

**判据**：红皮房产证观众看得懂是房产证，不需要上面字清晰。
**要"看得出性质"，不要"读得出内容"。**

## 六、★ Stage2 必须 identity 预设

- 官方 `0.909375` 起点 = **latent 里 91% 被噪声顶掉 = 近乎从零重画**
  → 这是"精修后脸被画坏 / 中文印刷变乱码"的直接机理。
- `identity` 起点 0.5 保留一半原 latent，**零成本**（75.0 vs 75.3 s）。
- 命令：`s2_adapt.py --preset identity --width 768 --height 1344`。
- 服务器缺 `dev-transformer` / `distilled-lora-450` / `taeltx2_3_wide.pth`
  → 用融合版 `ltx-2.5-22b-distilled-transformer-comfy-int8-convrot` + 删 LoRA + `VAEDecode`。

- v3 的"原声锁"用的是 `orig_audio/`（**从原片提取的真人声**）。

- 干声必须 **pad 到镜长**（`apad=whole_dur=`），否则音频短于视频窗口。

## 八、坑位清单

| 坑 | 现象 | 规避 |
|---|---|---|
| 双重栅格 | 填任意秒数 → 静默变形，字幕轴全错 | 只能取档位值（`retime_shots.py`） |
| `ts()` 格式 | 输出 `5.042` 而非 `00:05.042`，把 24 镜 prompt 写坏 | 修好后靠 `.orig_retime` 备份还原 |
| SaveVideo 白名单 | `--set` 打 `format/codec` 连键带值消失 | 不用 `--set`，逐镜生成完整 JSON |
| 顶层 `_meta` | `/prompt` 报 `missing_node_type: ID #_meta` | API 工作流顶层不能有 `_meta` |
| identity_locked 从未加载 | 驱动第 48 行读 `manifest.json`，补丁白做 | **一个片只留一份权威 manifest** |
| `/free` 返回体 | HTTP 200 但**响应体 0 字节** | 不要 `json.loads` |
| 字幕兜底写死 15.04 | 全片改成弹性排期后累积误差 | 改读 manifest 逐镜 `duration` |
| 冷启 vs 热态 | A100 首镜 382 s、热态 74 s，**差 4–5 倍** | 排期用热态批处理口径 149 s/镜，别拿首镜外推 |
| edge-tts 偶发失败 | 单镜 TTS 报 exit 1 | 重试 3 次即可，不是系统性问题 |

### ★ 审查时必查的六个维度（下次直接用）

1. **承诺-兑现**：台词许诺的东西，结局给没给？（片1 就是这么中的招）
2. **前置交代**：关键数字/人物首次出现时，观众有没有参照系？（片2 三十万、小勇）
3. **道具连续性**：同一个物件在前后镜的存放位置、状态是否一致？（片1 红绒布袋→内胸口袋）
4. **物理时间**：镜头内时间能否支撑状态变化？（片3 水桶接满）
5. **用语与场景匹配**：台词动作在当前场景可能发生吗？（片1「绝不下轿」但新娘在娘家未上轿）
6. **命名体系统一**：同一故事里不要中韩/中西混用。（片3 振浩 + EUN-HEE + MADAM-PARK + 人民币）

### P1 中**明确不改**的两条（写下来防止以后反复纠结）

- **片2 新娘全片缺席**：纯雄性视角（大院/唢呐/摩托/戈壁）是风格选择，硬加破坏调性。

## 十四、「定心丸」字幕根因查明 + f3s06 修复验证（2026-09-18）

### 用户反馈
- "原来你们要的定心丸" 出现在画面上
- 人物表情特别僵硬
- 要求：查明原因、重跑这一镜、全文审查提示词

### 根因 1 · `<d>` 标签把台词渲染成屏幕字幕
24 镜 prompt 里 **21 镜**含 `<d>[Chinese] "..."</d>` 标签。
这是 MiniMax H3 的 **dialogue 结构化指令**，作用本应是驱动口型，
但训练数据里台词与屏幕字幕高度绑定 → 模型会把 `<d>` 内的中文字
**直接当作要渲染的画面文字**处理。

尾部自然语言的 `strict_output_constraints`（"no subtitles"）优先级
远低于结构化 `<d>` 标签，所以禁字条款失效。

**f3s06 的 `<d>` 内容正是**：
```
<d>[Chinese] "原来你们要的定心丸，是一百二十万的替死鬼。"</d>
```
→ 这就是"定心丸"字幕出现的直接诱因。

### 根因 2 · 表情僵硬的 prompt 病因
扫描 24 镜发现：
- **20 镜微表情提示 < 3 个**
- 过度静态词：`spine straight and unnervingly calm` / `completely motionless` / `frozen in place` / `deadly pale silence`
- 缺少：`jaw tighten` / `blink` / `swallow` / `lip tremble` / `muscle twitch` / `eyes narrow` 等
- 缺少情绪 transition（`flickering then vanishing` / `settles into`）

H3 是音频驱动视频，**干声决定口型**，但面部肌肉/神态由 prompt 描述。
当 prompt 全是"冷静/僵硬/不动"时，生成出来的人物就真的是木乃伊。

### f3s06 修复方案
1. **去掉 `<d>` 标签**：`<d>[Chinese] "..."</d>` → `delivers an icy verdict in Chinese`
2. **新郎加动态**：下颌收紧、脸颊肌肉跳动、缓慢吸气、冷笑一闪而过
3. **母亲/新娘加微表情**：rapid blinks / mouth slightly open / visible swallow / trembling lower lip
4. **加 transition**：a brief cold half-smile flickering then vanishing / expression settling into merciless clarity

### 修复版验证（与原版对比）
| 项 | 原版 | 修复版 |
|---|---|---|
| 屏幕字幕 | 有台词文字风险 | **未出现** |
| 人物焦点 | 文件特写为主 | 人物表情+手部动作为主 |
| 新郎表情 | 面无表情/冷静 | 冷笑、下颌收紧 |
| 母亲/新娘 | frozen in place | 手部犹豫/颤抖 |
| 道具文字 | 文件上清晰可读 | **显著更模糊** |

**结论**：去掉 `<d>` + 增强微表情，**同时解决了字幕风险和表情僵硬**。

### 24 镜全量优化建议
- 21 镜 `<d>` 标签全部替换为自然语言
- 每镜至少加 3 处微表情提示
- 情绪转折用 transition 句式
- 把 `calm/still/motionless` 改为 "表面平静但内在紧张"（下颌收紧、呼吸变浅）

### 下一步
若用户确认，将批量修改全部 24 镜 prompt → 重新生成 24 个 wf_one → 全量一步直出。

### 三个流程要点
1. **`<d>` 标签是字幕的唯一直接诱因**——尾部自然语言禁令优先级压不过结构化标签，
   必须彻底移除，台词只由原声锁干声承载。
2. **位置锚点必须写进 prompt**——不写就是"每镜随机摆位"，剪辑后人物瞬移。
   已固化为场景坐标表，跨镜不得违反。
3. **自动扫描只查"有没有写"**，查不了"写得好不好"。表情自然度、位置是否真合理、
   画面有没有真出字幕，仍须**试拍目视**（第二关）。
