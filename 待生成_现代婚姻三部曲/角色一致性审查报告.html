一句话结论：三部片的角色描写都在"越写越省"——主角在前 1–2 镜给了完整定义（姓名＋五官＋服装），后面切到简写（只剩 the 30-year-old groom in black suit）。 而 H3 / LTX 管线是逐镜独立生成、镜头之间没有任何记忆：模型每开一镜都从零开始"画"这个人。写法一换，等于换了一个人。 其中《加名之夜》最严重——男主角 6 个镜次里一次都没给姓名和五官。

一、为什么"剧本写法"直接决定换脸

这套管线里，每一镜是一次独立的推理：Stage1 草稿吃 shot["prompt"] 生成低分辨率视频，Stage2 精修再吃同一段文本做重扩散。两次之间、镜头之间，除 seed 之外没有任何角色记忆传递（seed 全片固定，但固定 seed 只保证同一段文本出同一张脸，不保证两段不同文本出同一张脸）。

镜 01 的文本…groom named A-XING, slightly messy parted black hair, tired eyes with stubborn pride…
≠
镜 08 的文本…the 30-year-old lean groom in loosened black suit…

两段文本描述的是同一个人，但对模型来说是两套不同的条件 → 采样落在两个不同的"人脸盆地"里 → 观众看到换脸。这不是模型能力问题，是提示词工程问题。

推论（也是修复原则）：想让角色跨镜长得像，唯一可靠办法是让每一镜里该角色的身份描述逐字相同；镜头内"会变化"的部分（西装有没有解开、玫瑰还在不在、脸上有没有泪）另起短语写在动作句里，不进身份串。

二、逐片锚点覆盖矩阵

判定口径：FULL 有姓名 named X ＋ 五官锚点；MID 只有年龄＋服装，无姓名、无五官；SHORT 连年龄都缺。数字为该镜身份串里命中的"五官锚点数"（hair / eyes / jawline / features / skin / stubble / wrinkle）。

三、附带发现（不影响出片，但会误导下游工具）

1. character 字段不参与生成。我核对了 10_run_film.py：脚本只读 shot["prompt"] / file / no / framing / duration / dialogue_cn，character 字段既不拼进 Stage1 也不拼进 Stage2 —— 它是纯人读元数据。

2. 后缀 (ENV) / (HANDS) / (DEPARTURE) 只出现在《加名之夜》的 character 字段里（镜 01 / 05 / 07），不进模型，不影响出片；但它会让自动解析工具（比如本次审查脚本）把 Subject token 读错，建议统一去掉。

3. character 字段在多角色同框镜次漏列配角——《三十八万八》镜 01/03/06/07、《老子不娶了》镜 05/06/07/08、《加名之夜》镜 03/06 都只写了主角色。

4. 《加名之夜》镜 01 是纯环境镜（屋檐漏水 × 红桶 × 房产证），但 character 字段写的是 <Subject 1> (S1) (ENV) —— 标注与内容不符。

5. 《加名之夜》镜 05 是手部微距镜，prompt 里只有 <Subject 1> (S1)'s pale slender hands，没有任何身份锚点。作为手部特写可接受，但若希望手型/袖口跨镜一致，建议补 dark shirt cuff 一类锚点。

6. 对白对账全部通过（24 镜的 dialogue_cn 与 prompt 内 <d>[Chinese] 逐字一致；《三十八万八》镜 08 只是字段用 ……、prompt 用两个独立 <d> 段分隔，内容相同）。画面文字诱发项为零，24 镜 × 5 项负向词全部覆盖。

叙事连续性（不属于角色一致性，顺带提一句）：《三十八万八》镜 03 岳母台词是"不拿出这三十八万八，我家静静绝不下轿"，但同一镜画面里静静已经穿着婚纱坐在卧室刷手机——"不下轿"与"已在新房"并存，观众会读成逻辑漏洞。
