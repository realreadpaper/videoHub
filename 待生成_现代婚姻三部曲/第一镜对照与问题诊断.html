二、你看到的「效果不好」，主因不是画质 —— 是这三个

我把新版第一镜抽帧逐条看了一遍。锐度之外，有三个问题在伤害观感，其中两个是旧版完全没有的：

① 镜内硬切 —— 伤害最大 prompt 结构

15 秒里模型自己切了 3 个不同镜头。帧差 MAE 在中位 5 附近平稳运行，突然飙到 54 / 72（正常运镜的 10~14 倍）：

旧 prompt + TAEHV = 零硬切；新 prompt + TAEHV = 2 处硬切；新 prompt + 完整 VAE = 还是 2 处硬切。 解码器改不动它，因为根子在 prompt —— 单次 15 秒生成里塞进了 3 个不同景别／机位的事件，模型只能用「跳」来兑现。

② 画面内文字全是乱码 模型上限＋prompt 自找

对比旧版同位置：纸条写的是 38800 + xining wedding fee —— 数字至少是对的。原因很直接：新版 prompt 里明确写着要模型「显示这行字」：

… the white paper displaying bold black marker characters
   reading "388000 yuan parking slot fee"

现有视频模型画中文／小字基本必崩，而剧本里有 5 处这样的显式文字诉求（388000 yuan parking slot fee、Twenty Thousand Additional Entry Fee、signature line、written loan figure: "1…"、胸花 reading Groom）。

这处是「可以完全规避」的。把文字诉求从 prompt 里删掉，改成后期用 Pillow 渲染一张纸条再 overlay 上去 —— 字绝对正确、清晰度可控、还能随时改文案。这条路的成本几乎为零。

③ 画面里自发烧了中文硬字幕（且乱码） prompt 副作用

根因：prompt 里的对白标签 <d>[Chinese] "…"</d> 让模型把台词画进了画面。

同时注意：prompt 结尾明明写了 no subtitles, no captions, no on-screen text, no watermark, no logo —— 这些负向词完全无效，模型该烧还是烧。所以别指望用 negative prompt 解决，得从源头（对白标签的位置／写法）入手。

三、哪些是模型的天花板，哪些是用法问题

现象性质能不能修怎么修
画面偏软、细节少 管线 已修好 A1 完整 VAE 解码（本轮已验证）
镜内硬切、观感断裂 用法 能修 一镜一事件；要分段叙事改用 Prompt Relay 节点，别在正文写时间轴
纸条／招牌文字乱码 用法 能修 从 prompt 删掉文字诉求，后期 overlay 贴真字
自发光硬字幕 用法 能修 改对白标签写法；必要时后期 delogo 清残字
人脸「AI 感」、手部奇怪 模型上限 难 H3 22B 的固有能力边界，换模型或加 FaceRefine 才有实质改善
结论 2：不全是模型的问题。 你看到的「不好」里，硬切、文字乱码、自发字幕这三项全部是用法问题，都可规避；真正属于模型天花板的是人脸质感和手部结构。
换句话说：现在这版是在一个可修的问题上反复调解码器 —— 方向偏了。

四、官方其实有专门的分段机制，我们用错了

H3 的工作流目录里有一整套 14-prompt-relay（分段提示词时间线），它的设计是：

  • 全局约束（人物、服装、场景、风格、镜头连续性）写进 global_prompt，全程常驻；
  • 局部事件用独立的 Prompt Relay Event 节点绑定时间段，通过显式 chunk bias 路由注意力，而不是在正文里写「[00:05–00:10] 现在切换到…」；
  • 04-long-video 目录专门做分段长视频与断点续跑。

对比我们的做法：把三段事件全写进同一段文本、靠 [00:00.000 – 00:05.000] 标记分段。模型确实读懂了（所以它才在 8.8s／12.1s 切），但它只能用硬切兑现 —— 等于把「换镜头」的指令喂给了一个单镜生成器。

五、建议的下一步

  1. 先别再调解码器了。 A1 已经证明有效、保留即可，继续在这个维度抠是边际收益递减。
  2. 重写第一镜 prompt 做一次验证：一镜一事件、连续运镜；删掉所有画面文字诉求；调整对白标签避免烧字幕。同样跑 15 秒 × 362 帧，直接用本轮 A 版当基线对比。
  3. 验收标准（量化）：硬切尖峰从 2 → 0，且有效分辨率不低于 A1 版。这两条同时满足才算过关。
  4. 如确需镜内多事件叙事，再上 Prompt Relay 节点做正式方案，而不是在 prompt 正文写时间轴。
关于「都要一次生成 15s」：本轮两版都是标准单次生成 —— 草稿 362 帧（15.08s）一次出，精修输出 361 帧，没有任何分段拼接。判据里的跳变全部来自 prompt 引导的内容切换，不是生成能力不够。
