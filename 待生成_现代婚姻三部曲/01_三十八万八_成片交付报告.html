二、三轮迭代：硬切是怎么被打掉的

同一套模型、同一个 seed、同样的 A1 完整 VAE 解码 —— 唯一变量是 prompt 的写法。

v3 · 第一步

01–05 归零，06/07/08 各剩 1 处
v4 · 终版
单段连续叙述
把三段时间轴彻底压成一段，动作靠「先…接着…然后…」串联，不留任何分段标记。
8 镜全零硬切

为什么分段标本身就是硬切的诱因

[00:00–00:05] … [00:05–00:10] … [00:10–00:15] 这套写法对单镜生成器来说， 等价于「这里是一个新镜头」的强暗示 —— 即便正文已经写明 single continuous take, no cuts，模型仍会按段兑现成硬切。 最刺眼的是镜08：前 5 秒是完全静止的远景（帧差 0.1~0.4），第 5.54 秒突然跳到 43.9 （68 倍），因为 prompt 写了 the camera fully static at first。 v4 删掉这句、让镜头从头到尾都在缓慢推进，同一时刻的最大帧差就掉到 4.48。

四、字幕与「不烧进画面」

  • 成片全程无烧入字幕，8 镜残字扫描全绿。镜02 上一版曾糊着一行乱码中文硬字幕， 根因是 prompt 里明写「画面显示这行字」，v3 起已删除，本次该位置画面干净。
  • 字幕以独立 .srt / .vtt 交付，与成片同目录同名，可随时开关、改字不用重编码。
  • 待优化项：目前 8 条字幕里只有镜02 靠静音检测对齐了真实语音（5.54~11.68 s）， 其余 7 条因 H3 原生音轨被环境音盖满（有声占比 90~100%），回退成「整镜覆盖」。 下一版可接 TTS 重配音，用唇动检测自动定位口型区间，把字幕和配音一起对齐。

五、怎么复现这一版

全部脚本在 待生成_现代婚姻三部曲/_后期/，远端工程目录 /workspace/films/thirty_eight_eight/。

步骤命令
1. 生成 v4 剧本 python3 _后期/rewrite_prompts_v4.py --src 01_周星驰_三十八万八/manifest.json --out 01_周星驰_三十八万八/manifest_v4.json --shots 6,7,8
2. 上机出片 cp manifest_v4.json manifest.json → python 10_run_film.py --shots 1-8
3. 拉回底片 scp root@…:final/shot0N.mp4 01_周星驰_三十八万八/shots/
4. 一键验收 python3 _后期/acceptance_check.py --film 01_周星驰_三十八万八
5. 合成成片 python3 _后期/finish_film.py --film 01_周星驰_三十八万八

可回滚：远端留有 manifest_v2_backup.json / manifest_v3_backup.json， v2 全套产物归档在 /workspace/v2_baseline_3seg/。
