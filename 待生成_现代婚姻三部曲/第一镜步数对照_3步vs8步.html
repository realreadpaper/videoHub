《三十八万八》· 镜 01 · 步数对照实测

把「3 步」改成「8 步」——会好，但好得太少，不值这个价

同草稿、同提示词、同 seed、同注意力后端、同解码器，唯一变量是 sigma 序列。三臂实测给出可复现的判定： 锐度确实涨了约 16%，有效分辨率只挪 0.16 dB，而镜内硬切一处没修，代价是多花 39% 时间。

日期 2026-09-15 算力 RTX 4090 · 峰值显存 21.518 GiB（三臂完全一致） 结论 不采纳 8 步，保留 3 步 + A1 解码

一句话判定

8 步不是"没效果"，是"性价比崩了"。它带来约 16.5% 的锐度提升（361 帧里 317 帧胜出，可复现）， 但有效分辨率探针只挪 0.16 dB——只有上一轮 A1 解码器修正收益（2.35 dB）的 约 7%， 代价却是单镜从 172 秒涨到 239 秒（+39%）。

而它完全没能修掉你真正看出来的毛病：镜内硬切仍是 2 处，位置分毫不动（8.79s / 12.12s）。

更关键的是原理层面：这 3 个噪声水平是配套蒸馏 LoRA 训练过的，往中间插值属于分布外（OOD）。 官方把这个路线明确标成实验性、official_stage2_parity = False。

1步数到底藏在哪：它不是参数，是硬编码

这是整件事的关键。翻源码后确认：Stage2 没有"步数"这个旋钮可拧。

# h3_t8/sol_engine_h3_super_advanced.py:16
OFFICIAL_STAGE2_SIGMAS = (0.909375, 0.725, 0.421875, 0.0)   # ← 3 步调度写死在这里

# 节点 MiniMaxH3SolEngineLTXRefinerSetupT8Advanced 的全部输入只有 6 个：
#   model / enabled / attention_backend / min_tokens / kernel_precision / verbose
# 没有任何 steps / sigmas 参数。它把 sampler 和 sigmas 一起当输出吐给采样器：
#   outputs = [model, sampler, sigmas, refiner_lora_strength, report_json]

也就是说，工作流里那个"3-Step Refiner Setup"节点，是把调度**打包在代码里**输出给 SamplerCustomAdvanced 的。想改步数，只有一条官方留的门：

官方手动入口 = 同族的 Identity 精修节点 MiniMaxH3SolEngineLTXIdentityRefinerSetupT8Advanced 带 schedule_mode（manual_exp）+ manual_sigmas 字符串，可以直接写任意 sigma 序列。
而且它是无损替换：这个节点的 5 个输出与原节点逐位一致（model / sampler / sigmas / refiner_lora_strength / report_json）， 所以换类型后原来的 5 条连线一条都不用动。这一点我做了断言验证（见第 3 节）。

8 步是怎么构造的

不破坏官方锚点、也不改端点，只把三段间隔等分：

官方 3 步：0.909375 → 0.725 → 0.421875 → 0
间隔      ：   0.184375     0.303125    0.421875
8 步切分  ：   ÷3           ÷3          ÷2      （合计 8 个区间）

0.909375 → 0.847917 → 0.786458 → 0.725 → 0.623958
         → 0.522917 → 0.421875 → 0.210938 → 0

2为什么说"理论上也不该指望它"

这不是我推测，是官方节点自己的描述和报告字段写的：

证据原文 / 含义
调度与 LoRA 是配套的 官方节点说明："Configures the official LTX-2.5 Stage-2 Euler schedule [0.909375, 0.725, 0.421875, 0] … Apply the official LTX-2.5 distilled LoRA at the returned 0.8 strength" —— 蒸馏 LoRA 就是为这 3 个噪声水平训练的，强度 0.8 是配套值。
节点自带"非等价"声明 Identity 节点的报告里固定写 official_stage2_parity: False， pipeline: ltx25_stage2_identity_preserve_low_sigma_exp， is_experimental = True。它不是官方 3 步的等价替代，是一条实验支线。
注意力加速策略无法沿用 官方 per-step tau 递进是 (1.0, 1.25, 1.5)，与那 3 个 knot 一一绑定。自定义 knot 无法映射，只能退成常数 tau=1.0。本机没装 sol 后端（见第 5 节），这层本轮不影响结果， 但一旦将来装上，自定义步数就天然失去官方调优。
官方自己的边界说明 报告里写着："it is not NVIDIA's official distilled Stage-2 schedule and needs human identity/detail review" —— 需要人工复核主体一致性与细节。

一句话：插值出来的中间噪声水平，模型没被训练过该在那儿做什么预测。 多走几步并不会自动变成"更精细的积分"，因为每步的落点都偏了。

① 换节点在同等 sigma 下行为完全等价，我引入的改动零副作用；
② 整条 Stage2 是确定性的——固定 seed 下没有任何随机性。
顺带得出一个反直觉的推论 既然流程完全确定，"同一配置重跑一遍换个更好的"这件事不存在——重跑一万次也是同一帧。 想换一版，必须改输入：提示词、种子、或调度。
这条也意味着：本页所有差异都是真实可复现的效应，不是随机波动，不能拿"噪声"解释掉。

5顺带挖到两件比步数更要紧的事

① 所谓 "Sol-Engine 加速" 在这台机上是空名——Stage2 一直在跑稠密注意力 工作流文件名写着 Super_Acceleration_LTX25，官方节点也提供 auto_sol_attn 后端。 但实测本机 既没装 ComfyUI-SolAttn_triton，也没装包内文档审计过的 Saganaki22/ComfyUI-sol-attn（custom_nodes 下无相关目录， /object_info 里也没有对应节点）。
源码 find_loaded_sol_attn_backend() 找不到模块就返回 None，两个精修节点都静默回退稠密。 也就是说：那 47 层稀疏近似根本没生效，一直按精确注意力在算。
这是纯加速机会，不涉及画质取舍——但有个坑要先排：Sol-Engine 节点找的是路径含 solattn_triton 的模块，而包内文档普遍不认证 triton 变体、只认 Saganaki22 那套。 两条路的名字对不上，装之前得先做一次兼容性审计，别直接上。
② 烧字幕复查：镜 01 两版都干净，你要的"不进视频"已满足 用项目里已验证的残字扫描器（v3：形状 + 锐利度 + 跨帧持续三重判据）跑实验版： B_exp_8step.mp4 → ✔ 干净，控制组与基线像素等同，同样干净。
镜 01 本来就不烧字——它的对白虽然是 <d>[Chinese] "爸，等会儿进去你别紧张，一切有我。"</d>， 但模型没有把它烙成字幕。真正烧字的是镜 02，根因是它的 prompt 里明写要画面显示文字： white paper displaying bold black marker characters reading "388000 yuan parking slot fee"， 结果渲染成 388ouie / pairir purring slot fee。
按你的要求，字幕一律走外挂文件（与成片同名同目录的 .srt/.vtt），后续再优化，不烙进画面。

6建议

  1. 保留当前配置：3 步 + A1 完整 VAE 解码。远端 final/shot01.mp4 与 workflows/stage2_vaedecode.json 已还原到这套（8 步只是实验，不进入生产）。
  2. 别再往步数上花时间。要提清晰度，下一个值得试的杠杆按优先级是： ① 装 sol-attn 拿免费提速（先做兼容审计）；② 靶面恢复 1920×1088 再下采样（显存高危，本机 21.5/23.5 GiB 还剩余量）； ③ 换取景/打光更简单的提示词，让模型少猜。
  3. 真正的病是提示词。硬切 2 处、且三次实验（旧版零切、A 臂 2 切、B 臂 2 切）都指向同一结论： 问题出在把 15 秒拆成三段并逐段写时间轴，不是解码器也不是步数。
    修法：一镜一事件连续运镜 + 删掉所有"画面里显示某行字"的诉求 + 对白标签外移到后期 TTS。 验收标准就一条：硬切 2 → 0。GPU 空着，一镜约 3 分钟（草稿 70s + 精修 172s）能出结论。
  4. 提醒：流程完全确定性 ⇒ 单镜一轮（草稿 70 s + 精修 172 s）约 4 分钟， 三部曲 24 镜一轮约 1.6 小时。配置定案前的任何重跑都是白烧 GPU，别再盲跑。
