为什么是两阶段

草稿阶段用 672×384 / 4 步 快速生成，再交给 LTX-2.5 精修到 1344×768。这条路径把"试错"和"出画质"分开：调提示词时只跑草稿，定稿后再精修，重跑成本低。

帧数必须落在 17n+5 网格上

H3 的 length 只接受 17n+5（≈24 fps）。本片取 362 帧（15.083 秒）；精修阶段 LTX-2.5 的 frame_policy=trim_to_8n_plus_1 再裁到 361 帧（8n+1），最终 15.042 秒。乱填帧数会直接报错或产生音画错位。

06已知限制与优化方向

  1. 单镜安全上限 15.08 秒（362 帧）。实测 17 秒起必然出现帧间跳变（帧差 MAE 从 2.5 跃到 38 以上）。人物特写是最敏感题材，动作/多主体镜头余量更小，上排产前先拿目标镜头单发验证。
  2. 角色一致性靠 Token 复述 + 同 seed，不是锁脸。工业化复用同一角色时，应改用 fl2va（首尾帧驱动）路径：先生成定妆图，再以首帧垫图驱动每一镜，漂移率可再降一个量级。
  3. 模型会自发在台词镜烧中文字幕，且渲染不稳、常出乱码。本片 Prompt 已显式抑制（no subtitles, no captions, no on-screen text），中文硬字幕由本地后期用 Pillow 渲染 + overlay 烧入。
  4. 台词为模型原生生成，个别字可能音近而非精确。某镜台词不达标时，只需重跑该镜，画面无需单独重生成。
  5. 音轨电平天然不齐（各镜独立生成）。合成阶段必须做两遍 loudnorm（I=-16 / TP=-1.5 / LRA=11）——单遍是动态估计，实测只能到 -18.5 LUFS。
  6. 画面文字需节制：ASCII 数字渲染干净；中文界面文字会糊，原稿的中文 HUD 应改写成纯数字。
  7. 原稿的 --no watermark,... 是 Midjourney 语法，H3 不认，改用自然语言负向约束写在 Prompt 尾部。
