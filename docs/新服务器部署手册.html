这份文档解决什么问题

本机 macOS 只做编排与后处理，视频生成跑在远端 GPU 上。旧服务器一旦关停， 那半边（ComfyUI + 71 GB 权重 + 生产脚本 + 音图资产）就没了。这份手册把「GPU 侧那一半」 完整列了出来——哪些项目、哪些文件、什么版本、从哪拿、怎么装、装完怎么验。 照着做，一台新机器 3~6 小时可恢复出片能力（大头是下权重）。

★ 卡数变了：本手册是「双卡」口径，现行形态是「只租 1 张 A100」

部署步骤完全一样（bootstrap/ 那 7 个脚本与卡数无关）， 但下面这四处必须换成单卡的做法，否则会踩坑或白付租金：

启动04_launch_comfy.sh both04_launch_comfy.sh single，且不需要 --database-url
跑批两 worker 分 keys（§9.2）单 worker：run_dy_single.sh / run_trilogy_single.sh
内存门槛≥ 100 GB≥ 96 GB（单实例仍常驻 ~57 GB）

3 · 两条恢复路径

路径 A · 旧机还在 → 整盘 rsync 首选，约 20 分钟

权重 71 GB，重下一遍要好几个小时。只要旧机器还活着，优先整盘搬。

# 在新机上执行
rsync -avzP --info=progress2 root@旧机:/workspace/  /workspace/
rsync -avzP root@旧机:/root/s2/ /root/s2/
rsync -avzP root@旧机:/etc/sysctl.d/99-net-speed.conf \
               root@旧机:/etc/sysctl.d/99-swap.conf  /etc/sysctl.d/

# ★ 整盘搬完必须做两件事，否则起不来

rm -f /workspace/instance_b.db.lock /workspace/ComfyUI/user/comfyui.db.lock
# 2) venv 里写死了绝对路径，跨机搬过来基本是坏的——重建，别偷懒
mv /workspace/venv /workspace/venv.broken
bash deploy/bootstrap/02_build_stack.sh

路径 B · 旧机已关 → 从零重建 3~6 小时

# 新机上（仓库已 clone）

4.3 不可退让的两条安装顺序

  • 装节点依赖时必须排除 torch/torchvision/torchaudio/numpy。T8 节点的 requirements 里若带上它们，会把已经装好的 cu130 torch 覆盖成 PyPI 普通版 → CUDA 不可用。

8 · 部署步骤

1体检（只读，1 分钟）

bash deploy/bootstrap/00_check_target.sh

它会报出 GPU 架构 / 显存 / 内存 / 磁盘 / 驱动 / ffmpeg / BBR 状态，并直接给 FAIL 或 OK。 别跳过——最容易出事的不是软件，是「内存只有 62 GB」或「compute capability 7.0」这类硬伤。

2系统层（3 分钟）

bash deploy/bootstrap/01_provision_os.sh

幂等，可重复跑。做四件事：apt 装 ffmpeg/aria2/sqlite3/build-essential； 建 /workspace/{ComfyUI,venv,trilogy,dy_key,dl,logs,opt} 与 /root/s2； 建 8 GB swap 并写 /etc/fstab + /etc/sysctl.d/99-swap.conf； 写 BBR 调优并 sysctl --system 生效。

swap 是兜底，不是扩内存

它的作用是防 OOM kill。真开始用 swap 时会慢到像卡死。 内存告警时正确做法是卸掉空闲的 ComfyUI 实例，不是加 swap。

3重建 Python 栈（10 分钟）

bash deploy/bootstrap/02_build_stack.sh

建 venv（Python 3.10.12）→ 装 torch cu130 → clone ComfyUI 锁 ee71d5c4 → 装 headless 依赖（kitchen 0.2.34）→ clone 3 个节点锁 commit → 装节点依赖 （排除 torch/numpy）→ 写 pip-freeze-lock.txt。

这个脚本是旧机 build_env.sh 的修正版，修了三个坑（commit 过时 / kitchen 版本旧 / 漏 KJNodes），见坑位 1–3。

4下权重（1~3 小时，最慢的一步）

# 建议挂 tmux，避免 ssh 断开
tmux new -s dl
bash deploy/bootstrap/03_dl_weights.sh
# Ctrl-b d 脱离，回来 tmux a -t dl

用 aria2c 8 线程从 HuggingFace 拉 6 个文件（约 71 GB）。 每个文件下完会校验字节数 + 解析 safetensors 头部。 幂等：已存在且大小正确的会跳过。

大陆机房怎么办

把脚本里的 HF=https://huggingface.co 换成 http://hf-mirror.com。但先 curl -L 测速再决定—— 旧机在泰国，ModelScope 实测 9 B/s（等于不通），HuggingFace 反而 35 MB/s。 机房决定答案，别照搬。

9 · 启动与跑批

9.1 双实例启动（现行形态）

# 实例 A · GPU0 · 8188
CUDA_VISIBLE_DEVICES=0 setsid nohup /workspace/venv/bin/python /workspace/ComfyUI/main.py \
  --listen 127.0.0.1 --port 8188 --vram-headroom 1 --use-ck-attention \
  > /workspace/logs/comfy_a.log 2>&1 < /dev/null &

# 实例 B · GPU1 · 8189   ★ 必须带独立 sqlite（四个斜杠）
CUDA_VISIBLE_DEVICES=1 setsid nohup /workspace/venv/bin/python /workspace/ComfyUI/main.py \
  --listen 127.0.0.1 --port 8189 --vram-headroom 1 --use-ck-attention \
  --database-url sqlite:////workspace/instance_b.db \
  > /workspace/logs/comfy_b.log 2>&1 < /dev/null &
参数作用
--use-ck-attention走 comfy-kitchen 的 INT8 注意力通路。A100（SM80）上唯一有效的注意力加速
--vram-headroom 1DynamicVRAM 额外留 1 GB 空闲显存
--database-url sqlite:////workspace/instance_b.db实例 B 的独立数据库。不加会 Database is locked
setsid … < /dev/null &三个都不能少。否则 ssh 会话一断，任务被带走
