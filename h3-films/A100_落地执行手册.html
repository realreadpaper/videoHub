三、A100 vs 4090：能力与速度预判

显存

40 GB HBM2
vs 4090 24GB GDDR6X —— 多 67%，offload 压力显著更小。实测 4090 上单镜峰值 23.2/24 GiB 已经顶格，A100 上会宽松很多

显存带宽

1555 GB/s
vs 4090 1008 GB/s —— 高 54%。diffusion 采样是带宽敏感型，这一项 A100 占优

算力（BF16/FP16 dense）

≈156 TFLOPS
vs 4090 ≈165 TFLOPS —— 基本持平。别指望算力带来的提升

精度格式支持

SM 8.0
INT8 ✓ · bf16 ✓ · FP8 ✗ · NVFP4 ✗ —— 这就是为什么只改 CLIP 一个文件
速度预判 → 已实测校准（2026-09-17 更新） 当时的基线取的是 4090「逐镜交替」口径：草稿 107–120s + 精修 139–148s = 248s/镜。
实测结果：A100 热态批处理 74.3 + 75.2 = 149 s/镜，与 4090 的同口径值 72.5 + 90.6 = 163 s 相比快约 9% —— 「同档」的预判成立，但当时写「或略慢」，方向错了。
⚠ 不要再拿 248 s 当 A100 的对照基线。248 s 是「逐镜交替」（每镜切一次权重）口径， 149 s 是「热态批处理」口径，两者相差 100 s/镜 —— 其中约 35 s 是每镜重装 TE+UNET 的钱， 与卡无关（草稿段 4090 热态 72.5 s vs A100 热态 74.3 s，本就同档）。
真正的收益仍是三条：① 显存不再顶格（稳定不 OOM）② 数据中心卡 + ECC，长跑无人值守更稳 ③ 片子能继续出。
需要你确认一件事：是 SXM4 还是 PCIe？ 40G 有两个版本，带宽差 66%：SXM4 = 1555 GB/s，PCIe = 933 GB/s。 上面按 SXM4 算的。如果你租的是 PCIe 版，带宽反而比 4090 略低，速度预判要下调到 −20% ~ +10%。 a100_bootstrap.sh 的 P1 阶段会打印 nvidia-smi -q 的 PCIe/SXM 信息，跑完就知道。

Ref2VA 路线要额外下（如果你要跑产品参考图）新情报

我上一轮的猜测被推翻了 —— Ref2VA 确实有独立权重 上轮我说「T8 节点文档说六种任务共用一个 latent，所以可能不需要单独权重，但不敢打包票」。 现在查到官方仓库里明确有：
  • diffusion_models/minimax_h3_ref2va_int8_convrot.safetensors —— 独立的 UNET
  • loras/minimax_h3_ref2v_turbo_8step_v1.0_768p_comfyui_bf16.safetensors —— Ref2VA 专用 LoRA（注意是 ref2v 不是 fl2v）
不能用 fl2va 顶替。这意味着走产品参考图路线要多下一份 UNET（int8 约 20GB+）。 a100_weights.sh 的映射表已经把这两个文件名认进去了，反查到就会下。

顺手挖到两个硬边界（会影响产品镜方案）

边界内容与影响
pruned INT8 在短边 < 512px 会结构崩坏 节点包文档明确写：Ref2VA 静态编辑时，pruned INT8 模型在 <512px 下结构崩坏，推荐 canvas_mode=from_edit_image 且短边 ≥512。
我们 stage1 是 384×672（短边 384） —— 所以 Ref2VA 路线不能直接套现有工作流， 要么改 canvas_mode 让画布从参考图继承（参考图短边做到 ≥512），要么把 stage1 提到 512 短边。 现有的 T2VA / FL2VA 路线不受影响（20 镜已实测跑通）。
引用上限 9 图 / 3 视频 / 3 音频。多图共用一个 ref_images 槽，编号必须连续 （<Picture 1..N>），且 strict_prompt_tags=true 会校验。 建议先单图跑通再上多图。
LoRA 加载方式 必须用 LoraLoaderBypassModelOnly 加载 —— 我们现有工作流已经就是这个节点，不用改。 另外「严禁再串联 SigmaShift 或外部 scheduler」（我们用的是双时钟 sampler，也已合规）。

七、ComfyUI 启动参数（A100 调优）

4090 是 24G 顶格跑，A100 有 40G，启动策略可以更宽松，减少 CPU↔GPU 搬运。

# A100 40G 推荐起法
cd /workspace/ComfyUI
/workspace/venv/bin/python main.py \
  --listen 0.0.0.0 --port 8188 \
  --disable-auto-launch \
  --bf16-vae \
  > /workspace/films/comfyui.log 2>&1 &

# 验证起来了
curl -s http://127.0.0.1:8188/system_stats | head -c 400
参数为什么
--bf16-vaeA100 原生支持 bf16，VAE 走 bf16 比 fp32 快且省显存
不要加 --lowvram40G 够用，加了反而强制分层搬运、变慢。4090 时代才需要
不要加 --fp8* 系列A100 无 FP8 硬件，加了会走模拟路径，更慢
视情况 --reserve-vram 2如果想给系统留余量，防止长时间跑后碎片化 OOM
显存账（帮你判断要不要调） 单个阶段不会同时驻留 UNET 和 CLIP：文本编码先做、做完释放，再加载 UNET 采样。
峰值估算：UNET int8 ≈ 21GB + 激活 ≈ 2–3GB ≈ 24GB 左右；CLIP int8 = 27.14GB。
两者都在 40GB 内，理论不需要 offload。但 CLIP 27.14GB 是单文件较大的一个， 如果实际出现 OOM，优先加 --reserve-vram 或临时降到 bf16 VAE，别急着上 --lowvram。

十一、排错表

症状最可能的原因处置
NoCapableBackendError
no kernel image is available		 comfy-kitchen 在 SM 8.0 上没有对应 kernel（全方案最大未知数） 从源码重编，显式指定 --cuda-archs="80"；或确认 torch 是 cu130 build
400 value_not_in_list clip_name 缺 minimax_h3/ 前缀，或引用了不存在的文件名 检查 P3 探测的「权重盘点」输出，确认目标文件真的在 text_encoders/minimax_h3/ 下
OOM（CLIP 阶段） int8 CLIP 27.14GB + 显存碎片 加 --reserve-vram 2；或确认没有别的进程占卡（nvidia-smi）
速度比 4090 慢很多（>1.5×） 走了 offload / fp8 模拟路径；或租到的是 PCIe 版（933GB/s） 核对启动参数（别加 --lowvram / --fp8）；P1 阶段确认是 SXM4 还是 PCIe
Ref2VA 出的画面结构崩坏 pruned INT8 + 短边 <512px 已知会崩 改 canvas_mode=from_edit_image 让画布继承参考图（参考图短边做到 ≥512）
参考图接上了但产品没变化 prompt 里没引用 <Picture 1>，图片未被认领 我们的 prompt 已经写好引用（build.py 有硬校验拦这个）；若手工改过，检查标签编号连续
画面又出现乱码字 生成层压不住（4090 时代就实测压不住） 后处理 S3 字幕带处理（clone 方式）兜底；同时查 prompt 里有没有成对的英文引号包住中文
投送后发现远端还是旧权重 先投了工作流、后改的 CLIP 顺序必须是「先 a100_patch_clip.py、再 deploy_voice.sh」；投完 grep 复验

十二、验收清单

阶段 1 · 环境就绪

  • ☐ nvidia-smi 显示 A100 40G，驱动 ≥ 580
  • ☐ torch.version.cuda 是 13.x，torch.cuda.is_available() 为 True
  • ☐ check_gpu_compat.py 退出码 0 或 2（不是 3）
  • ☐ comfy-kitchen 可 import，无架构报错
  • ☐ ComfyUI + T8 节点包在位，8188 端口可访问

阶段 2 · 权重就绪

  • ☐ 反查清单里所有 .safetensors 都在位（无 ✘ 项）
  • ☐ CLIP 用的是 int8_convrot 版，不是 nvfp4
  • ☐ 若走 Ref2VA：minimax_h3_ref2va_int8_convrot + ref2v_turbo LoRA 都在位
  • ☐ /workspace 剩余空间 ≥ 20GB

阶段 3 · 单镜通过

  • ☐ 镜 5 草稿 + 精修都出片，日志无后端报错
  • ☐ 成片规格 768×1344 / 24fps / 361 帧 / 双声道
  • ☐ 音轨是中文干声原文（转写回来比对一致）
  • ☐ 峰值显存 < 40GB，无 OOM
  • ☐ 单镜耗时在 4090 基线的 1.5× 以内
  • ☐ 画面无乱码字幕（有则记下来走 S3 兜底）

阶段 4 · 批量交付

  • ☐ 片1 20 镜齐（final/shot01..20.mp4）
  • ☐ 片1 回传本地后跑通 post_produce.sh
  • ☐ 成片时长对齐原片（286.13s ± 1s）
  • ☐ 字幕是外挂 .srt，没有烧进画面（铁律）
  • ☐ 片2 同流程走完
