三、角色锚定 —— 本轮最重要的修复

症状 已定位

跨镜人脸漂移；实测镜 05 里 65 岁的顾董被画成了年轻西装男。

根因

H3 是单镜生成。而 40 镜里最初只有 2 镜（片1 镜01、片2 镜16）的 prompt 带了角色外貌描述， 其余镜里角色只以裸标签 S1/S2/S3 出现 —— 模型每镜都在自由发挥。这正是「角色没保持一致」的根因。

处置 已实施

在 pN_data.py 的 _prompt() 里自动注入「角色锚定块」：

  • 从 beats + sound 文本按词边界识别出场标签 （S2K / S2_STAND 优先于 S2，避免前缀误配）；
  • 在 integrated_multimodal_description: 之后插入一整行角色定义；
  • 画面里出现 pouch / packet / sachet 时自动补锚产品 SP → 跨镜产品外观一致；
  • _shot(..., cast=[...]) 可显式指定（片2 镜16 男孩站起来用 S2_STAND）。

  2. 台词说话人补锚（关键）：镜05 的 beats 只写「the man on the ground」、 从未引用 S1，所以锚定列表最初漏掉了躺在地上的顾董。 改为「beats 标签 ∪ 台词说话人」后，顾董才被锚定 —— 他才出现在画面里；

五、TTS 时长布局（make_tts v3 · 当前口径）

症状

40 镜里 38 镜语音超出 15.0833 s 窗（最长 16.67 s），干声尾巴会盖到下一镜 → 台词听不全。

v2 的错误假设（已被 v3 实测推翻）

先入为主地认为「溢出 = TTS 语速太慢」，于是写了一套「迭代加速到 +90% / +150%」。 实测证明跟语速基本无关，真正的两个根因是：

  1. edge-tts 的 rate 在 +50% 处封顶 —— 同一句 +50% / +100% / +200% 时长完全一致（都是 1.872 s）。 所以 MAX_RATE=150 是假的，那几轮「加速」全是无效空转。
  2. 每句 TTS 产物的首尾都垫着 0.4–0.9 s 静音 —— 实测「束一半了。」总长 1.872 s， 真实语音只占 0.184 s → 0.995 s（0.81 s），尾部 0.88 s 全是静音。 8 句一镜就白扔 5–7 s。这才是 38 镜超窗的真凶。

v3 处置 已实施

  1. 合成：默认 rate=+40%（edge-tts 有效区间内，听感比 atempo 更干净）；
  2. 裁静音：silencedetect（-45 dB / 0.05 s）定位语音区间 → atrim 裁掉首尾静音，仅保留 0.03 / 0.06 s 呼吸；
  3. 排布：按裁剪后实测时长首尾相接，句间留白均分，落在 [0.06, 0.75] s；
  4. atempo 兜底：若裁剪后仍塞不下，用 ffmpeg atempo 变速 （不受 edge-tts 限制、不改音高），数学上保证 end ≤ 窗长。
