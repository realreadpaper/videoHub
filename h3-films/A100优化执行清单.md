## 〇、口径约定（本清单所有时间数字按此读，2026-09-17 统一）

同一件事有**三种计时口径**，混用会得出差 4 倍的工期：

| 口径 | 单镜 | 定义 | 用途 |
|---|---|---|---|
| **A · 热态批处理** | **149 s**（74 + 75） | 同进程连跑、权重已驻留 | **凡排期一律用这个** |
| B · 逐镜交替 | 248 s | 每镜在 S1/S2 之间切一次权重（09-16 4090 实测 107 + 139） | 反事实参照 |
| C · 每镜冷启 | 652 s | 每镜都把 45 GB 权重从磁盘重读一遍（382 + 270） | 反事实**上界** |

**铁律**：冷启类数字（S1 首镜 382 s、S2 冷启 271.6 s）**只在一个批次的第一镜付一次，绝不乘 20**。
B 口径里草稿 107 s 比热态 74 s 多出的约 35 s，正是每镜重装 TE(25.9 G)+UNET(20 G) 的钱。
推导见 `产品高清方案.html`「口径二 / 口径三」。

## 二、已被实测否决的优化——**不要重试**

1. **SageAttention / 一切 attention 后端替换**：`--use-sage-attention` 后采样输出全 NaN
   （`ValueError: nonfinite IMAGE`），已 pip uninstall 回滚。**int8_convrot 管线对 attention
   数值精度敏感，flash_attn / xformers 同理不要装。**
2. **`--fast` 启动参数**：SM 8.0 无原生 FP8，实测冷启 472 s 反而更慢，热态无收益。
3. **降步数**：当前 4 步已是最低 LoRA 档（fl2v_turbo_8step / ref2v_turbo_4step / turbo_v4_step600）。
4. ~~换 4090 48G~~（用户拍板剔除）、~~FastVideo FP8/VSA 4090 配置~~（同理剔除）。

## 三、有效杠杆（按收益排序）

1. **同进程连跑批处理（最大单项收益）**
   20 镜在同一 ComfyUI 进程里连续提交，同批内**不插 Stage2、不调 /free、不切分辨率**。
   收益区间 **25–161 min**：冷启开销只在批次首镜付一次（S1 382 s、S2 271.6 s），
   若逐镜各付一次，20 镜从 58 min 涨到 217 min（C 口径）。
   ⚠ 下界取 4090 实测的逐镜交替（248 s/镜 → 83 min）；**A100 上的逐镜交替没测过**，
   所以"省多少"这个数目前只有区间。想钉死只需跑一镜 `S1 → /free → S2`（约 6 min）。
2. **每镜构图分层（与耗时无关，纯画质）**
   - ★ **产品镜在耗时上与普通镜同档**：热态批处理口径下，产品镜 = S1 ref2va ~77 s + S2 identity 75 s
     = **≈152 s**，普通镜 = 74 + 75 = **149 s**，差 3 s（ref2va 采样 12.21 vs 11.4 s/it，噪声量级）。
     —— 早前记的「产品镜 360+280 ≈ 640 s」是**两步各自冷启**口径，**不能当成本用**（见 §〇）。
   - **产品镜（s13/s15）真正的差异只在画质侧**：S1 用**特写构图**（产品占画面 ≥70%）；
     S2 用 `--preset identity`（sigma 0.5→0.412→0.350→0）保脸保字，印刷还原 ~95%。
     直出 768（631 s）仅在必须 ~100% 还原且接受 98.5% 显存时用。
   - 分层依据：S2 只能放大 S1 已「看见」的细节；特写要在 S1 就做，提分辨率救不了中景。
3. **阶段化 P1–P4 + 只在阶段边界 /free**
   P1 S1 条件编码 → P2 S1 采样（fl2va 18 镜一批、ref2va 2 镜一批，UNET 只切一次）→
   P3 S2 条件编码 → P4 S2 精修。避免两套权重在 62 GB 内存里互相淘汰导致的 25 min 级磁盘回落。
4. **P1/P2 条件三件套落盘（SaveConditioning / SaveLatent / SaveAudio）**
   省时仅 2–5 min，真正价值是 S2 采样段显存 98% → 56%（唯一 OOM 风险点解除）+ 可断点续跑。
   注意：SaveConditioning 落在 output/，需移到 models/conditioning/ 才能被 ConditioningLoader 列出。
5. **页缓存预热**：阶段开始前 `vmtouch -t`（或顺序 cat）当前阶段权重，把冷读盘挪出关键路径。

## 四、质量护栏（A100 特有）

- **禁换 attention 后端**（NaN 实锤，见 §二）。
- **产品/人脸镜一律 `--preset identity`**（sigma 0.5→0.412→0.350→0，低强度保脸保字）；
  official 满强度（0.909→0）会把产品重画成乱码、换人脸。
- **品牌文字 100% 靠合成贴图兜底**：生成画字是概率性的（同镜 t=7s 正确、t=12s 出形近字），
  prompt 只写「壳」（clean unprinted / no legible lettering），`overlay_product.py` 贴回真图。
- **权重文件不可删**：aimdo 靠 mmap 文件做后备仓库，删 .safetensors 等于删模型。
  下新权重前先扩盘（剩 9.3 GB；dev+LoRA 版需 28.3 GB，现用蒸馏融合版零新增）。
- **/free 返回空 body**：判断成功只看 HTTP 200，不要解析响应体。
- **SaveVideo 的 COMFY_DYNAMICCOMBO_V3 修复**（format/codec 参数）必须保留在 UI→API 转换链路里。
- S1 工作流是 UI 格式，远端需 `ui_to_api.py` 转换后再提交；CLIP 权重必须先用
  `a100_patch_clip.py` 换成 int8_convrot（A100 唯一必改项）。


★ **写法变了，务必注意**：不能再写成「18 常规镜 × 150 s + 2 产品镜 × 640 s」——
