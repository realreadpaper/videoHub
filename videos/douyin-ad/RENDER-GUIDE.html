唯一已知风险

全局 hyperframes 是 0.8.41，而 hypit provider 声明依赖 0.7.101。 check / plan 两关都通过，所以配置层没问题；若渲染时报引擎或版本相关错误， 执行下面这条即可（render-local.sh doctor 也会提示）：

npm i -g hyperframes@0.7.101

备用通道：远端渲染

如果本机不方便，或想丢给常开的服务器 —— 给我 IP 即可。成片渲染全程只吃 CPU，不需要 GPU。

bash ~/Desktop/videoHub/remote-render/render-on-remote.sh \
  --host root@你的IP # 可选 --port 22024 --slim --dry-run

远端要求：Debian / Ubuntu 系 · 有 sudo · 磁盘 ≥5 GB · x86_64（headless-shell 官方只发 x86_64）。

共 4 个远端专属坑已全部写进 bootstrap 脚本并实测：ffmpeg 必须 ≥8（7.x 会静默丢帧）· npm 发布版缺 112 个内部包软链 · headless-shell 无 arm64 构建 · HYPERFRAMES_BROWSER_PATH 需显式注入。
为什么之前在本对话里跑不出片：本环境对文件删除做批量计数（阈值 50 / 每个 turn）， hypit 渲染收尾清理自己的临时产物时会被打断。你自己的终端没有这层限制。
