Hypit · 自部署模型接入

能不能用自己服务器部署的模型生成视频？

能。这是官方文档里明确列出的第一等扩展场景，不是绕路。
但真正决定成本的是你的推理服务长什么样 —— 协议像不像、能力对不对得上、机器扛不扛得住。这份说明把三条路径、硬约束和现实门槛讲清楚。

1 · 为什么能接：capability 是模型身份，不是服务商

Hypit 把「生成视频」这件事拆成三个互不绑定的层：

Model —— 定义要生成什么。输入端口、参数取值、输出类型。比如 @hypit/seedance@1 声明的 TextVideo / FrameVideo / ReferenceVideo 三种调用形状。

Provider —— 知道怎么通过某个服务完成这个请求。它是 capability 的实现者。

Endpoint —— 配置好的 Provider 实例：服务地址、凭据、并发容量。写在一个 Runtime Profile 里。

Profile 的 bindings 把「需要什么能力」和「由哪个 Endpoint 兑现」接上。

关键在这里：SVML 作者写的是 capability，不是服务商。

<seedance:TextVideo id="take" model="mini" prompt={direction} duration="5"/>

这行源码编译出的需求是 @hypit/seedance@1#seedance-2-mini —— 一个模型身份。至于这个身份由腾讯的 HypiHub 兑现、还是由你自部署的推理服务兑现，是 Profile 层的事，SVML 不用改一个字。

值得注意

官方文档在「模型与 Provider」一章里，把「在自己的云部署上运行模型」列为修改位置表中的独立一行；在「模型与部署服务」里也明确写了：没有合作关系、没有官方内置 Provider，也可以使用一份合适的部署。这条路是设计出来的，不是绕出来的。

3 · 路径 A：协议兼容直连（零代码）

官方 @hypit/provider-hypihub 的 baseUrl 是可配置的，默认 https://hypit.ai/v1。如果你的推理服务实现了同一套 HTTP 形状，改地址就接上了。

需要实现的协议

用途端点要点
模型目录GET /v1/models/{model}强制。返回 { endpoints: ["videos"] }，必须包含 videos，否则提交前就报错
提交视频POST /v1/videos返回 { id } 或 { job_id }。请求体见下
轮询任务GET /v1/jobs/{id}status 取值：queued / running / in_progress / succeeded / completed / failed
取产物GET /v1/jobs/{id}/assets返回 { items: [...] }
上传素材POST /v1/files/uploads、/v1/files参考图 / 参考音 / 首尾帧
OAuth（可选）POST /oauth/token用 API Key 就不需要

POST /v1/videos 的请求体字段（videos 操作的规范化形状）：

{
  "model": "seedance-2-mini",
  "prompt": "…",
  "seconds": 5,
  "resolution": "720p",
  "aspect_ratio": "9:16",
  "generate_audio": true,
  "reference_image_urls": ["https://…"],
  "reference_videos":     ["https://…"],
  "reference_audios":     ["https://…"],
  "first_frame": "https://…",
  "last_frame":  "https://…"
}

认证走 Bearer：authorization: Bearer <key>。另外提交时会带一个 idempotency-key 头，用于幂等。

地址规范化规则

Provider 会把你配的 baseUrl 归一化：去掉尾部斜杠，剥掉末尾的 /v1 或 /v1beta，再统一拼上 /v1。所以下面三种写法等价，都指向 https://video.myserver.com/v1：

https://video.myserver.com
https://video.myserver.com/
https://video.myserver.com/v1

Profile 改法

{
  "endpoints": {
    "selfhosted.video": {
      "use": "@hypit/provider-hypihub",
      "config": {
        "baseUrl": "https://video.myserver.com",
        "apiKey":  { "store": "os", "key": "selfhosted.video" },
        "pollIntervalMs": 10000,
        "operationTimeoutMs": 3600000
      }
    }
  },
  "bindings": {
    "@hypit/seedance@1#seedance-2-mini": "selfhosted.video"
  }
}
前提要说清

路径 A 省事，代价是你的服务得长成 HypiHub 的样子 —— 包括那个强制的模型目录查询、任务 ID 的字段名、状态枚举、资产清单接口。如果你是自己写的服务，为了省一个 Provider 包去迁就这套形状，通常不划算。自写服务直接走路径 B 更干净。

4 · 路径 B：写项目 Provider（推荐）

项目 Provider 是放在你项目里的一个普通包。官方仓库里有一个完整的参考示例 examples/provider-package，我这边的骨架就是照它的结构做的。

已经给你备好的骨架

位置：videos/demo/packages/provider-selfhosted-video/，已编译通过（tsc 零报错，产物可导入）。

文件作用
src/provider.ts核心：端口映射表、支持性判定、提交 / 轮询 / 取产物三个生命周期方法
src/activation.ts读 Profile 的 config、校验地址、建实例
package.jsonhypit.activation 指向编译产物，Hypit 靠它找到入口
tsconfig.json与官方示例一致的编译配置

它为你做了什么

  • 复用官方 Seedance capability —— SVML 一行不改，seedance:TextVideo model="mini" 直接打到你自己的服务
  • 诚实边界 —— 只声明你的服务真正支持的端口；作者一旦用了不支持的端口，hypit plan 阶段就明确报错，而不是静默丢弃
  • 参考素材上传链路 —— 把 Hypit 侧的资源字节上传到你服务能取到的位置，再换成 URL 进请求体
  • 产物登记 —— 下载回来的字节登记为 GeneratedVideoSet，下游时间轴照常消费
  • 零调用费用声明 —— pricing: { kind: "local" }，算力成本归你自己的机器，Hypit 侧不计费

你要改的地方：就四处

1

顶替哪个 capability（provider.ts 顶部）

按 SVML 里的 model= 属性选，两处必须对得上：

SVML 写法capability 全名分辨率时长

model="2.5"@hypit/seedance@1#seedance-2.5480p / 720p / 1080p-1 或 4–30s
2

端口映射表 mapping.fields

左边是 Hypit 的端口名，右边是你服务的 JSON 字段名。只声明你的服务真正接受的端口。Seedance 的端口全集是这些：

端口含义类型写法
prompt提示词（普通 Text）{ as: "value" }
duration时长（整秒字面量）{ as: "value" }
resolution分辨率{ as: "value" }
aspectRatio画幅比{ as: "value" }
firstFrame / lastFrame首帧 / 尾帧{ as: "url" }
referenceImage参考图（可带 personReference）{ as: "urlArray", resourceFields: ["personReference"] }
referenceVideo参考视频（运动 / 运镜依据）{ as: "urlArray" }
referenceAudio参考音频（音色）{ as: "urlArray" }
generateAudio是否生成同步音频{ as: "value" }
webSearch仅 TextVideo 形状开放{ as: "value" }
这一步最关键

自部署的 Wan 2.2、HunyuanVideo 都是无声模型。那就不要声明 referenceAudio / generateAudio / webSearch。作者写了 generate-audio="true" 时，plan 会直接告诉他这个 Endpoint 不支持 —— 这是好事，比跑到一半才发现花钱强。

骨架里假设的是最常见的「任务式 HTTP API」形状，改这三处的路径和响应字段即可：

pollGET /tasks/{id} → { state }
collectGET /tasks/{id}/files → { items: [{ url }] }，再下载字节
4

Profile 里接上

别被这个报错骗了

@hypit/hypit 的 subpath exports 里，import 指向的是 TypeScript 源文件（./packages/endpoint-kit/src/index.ts），types 才指向 .d.ts。

所以你用裸 node 去 import 编译产物时会看到 Stripping types is currently unsupported for files under node_modules。这不是包坏了 —— tsc 编译能过正是因为类型走的是 .d.ts；而运行时是由 Hypit Runtime 自己的模块解析器加载的，不是裸 node。

判断包能不能用，看 hypit doctor 的输出，别看裸 node import 的结果。

5 · ComfyUI 专项：最现实的一条路

自部署视频模型绝大多数不是以「干净的 HTTP API」形态存在的，而是 ComfyUI 工作流。好消息是 ComfyUI 的接口形状天然就是 start / poll / collect，而且默认监听 127.0.0.1:8188 —— 正好满足下面说的回环地址约束。

Hypit 需要ComfyUI 对应响应
提交任务POST /prompt，body { prompt: <API格式工作流>, client_id }{ prompt_id }
轮询GET /history/{prompt_id}进行中返回空 {}；完成返回 outputs 与 status.completed
取产物GET /view?filename=&subfolder=&type=output文件字节
上传参考图POST /upload/image（multipart）{ name, subfolder, type }
取消POST /interrupt—
健康检查GET /system_statsGPU 名、显存总量 / 剩余
最常见的失败原因

ComfyUI UI 里保存的普通工作流 JSON 不能直接提交。必须导出 API 格式：Settings → 勾选 Enable Dev Mode options → 出现 Save (API Format) 按钮，用它导出。API 格式只保留可执行图（节点 ID + class_type + inputs），没有画布位置信息。

骨架里怎么改

// start —— 提交工作流
const task = await json("/prompt", context.credentials, {
  method: "POST",
  headers: { "content-type": "application/json" },
  body: JSON.stringify({ prompt: workflowGraph, client_id: "hypit" }),
});
const id = text(task.prompt_id, "prompt_id");

// poll —— /history/{id} 空对象表示还在跑
const history = await json(`/history/${encodeURIComponent(id)}`, context.credentials);
const entry = history[id];
if (entry === undefined) return wakeAfter({ id }, interval, Date.now(), { phase: "running" });
// entry.outputs 里找视频节点（VHS 的 VideoCombine 输出常在 gifs 字段）
// entry.status.completed 为 true 表示完成

// collect —— 用 /view 取文件
const url = `${base}/view?filename=${encodeURIComponent(name)}&subfolder=&type=output`;

几个实操要点：

  • 工作流 JSON 里把 prompt 文本框、种子、时长、分辨率留成可替换的位置 —— 骨架里用字符串替换或按节点 ID 定位都行
  • 参考图先用 POST /upload/image 传进 ComfyUI 的 input 目录，再把返回的 name 填进工作流的 LoadImage 节点
  • ComfyUI 默认没有任何鉴权。别直接暴露到公网；用 SSH 隧道或反代加认证
  • 视频产物位置取决于节点：VHS 系节点在 outputs 的 gifs 字段，其他节点可能是 images。以你实际工作流的输出为准

6 · FastVideo 专项：这条路的接口已经备好了

关键发现：FastVideo 自带 OpenAI 兼容的 HTTP 服务，不用你自己再包一层。

fastvideo serve --config your-config.yaml --server.host 127.0.0.1 --server.port 8000

它暴露的接口（源码位置：fastvideo/entrypoints/openai/）：

端点用途
POST /v1/videos提交异步任务 → { id, status, progress, error }
GET /v1/videos/{id}轮询状态
GET /v1/videos/{id}/content下载 mp4 字节
POST /v1/videos/sync同步生成，直接返回 mp4（带 X-Inference-Time-S 等头）
GET /v1/models/{model}模型目录
GET /health健康检查

状态枚举是 queued / in_progress / completed / failed。

为什么不直接走路径 A（零代码）

步骤HypiHub 要求FastVideo 提供一致？
提交视频POST /v1/videosPOST /v1/videos路径一致
模型目录GET /v1/models/{model} → { endpoints: ["videos"] }GET /v1/models/{model} → OpenAI 模型卡路径通，响应形状不同
轮询GET /v1/jobs/{id}GET /v1/videos/{id}路径不同
取产物GET /v1/jobs/{id}/assetsGET /v1/videos/{id}/content路径不同
素材上传POST /v1/files/uploads无（引用走 image_reference 的 URL）缺

主路径对得上，但轮询和取产物的路径不同 —— 所以路径 A 走不通，走路径 B。好在差异都在 URL 路径上，改起来就是三处。

骨架已经改好了

packages/provider-selfhosted-video/ 现在默认就是 FastVideo 形状：start 打 /v1/videos、poll 打 /v1/videos/{id}、collect 打 /v1/videos/{id}/content。你要改的只剩 routes[0].model 的模型名，以及按你的模型能力决定是否打开 generateAudio。

请求字段对照

Seedance 端口FastVideo 字段备注
promptprompt直接对应
durationseconds类型宽松，接受整数或数字字符串
aspectRatioaspect_ratioFastVideo 原生支持，直接对应
resolutionsize骨架做了换算：720p + 9:16 → 720x1280
referenceImageimage_reference形状是 [{ image_url }]，骨架用 itemObject 映射
generateAudiogenerate_sound按你的模型能力决定是否声明
一个真实卡点

FastVideo 的素材引用只接受 URL（image_reference: [{ image_url }]），而它没有上传端点。所以「图生视频」这条链路上，得先有地方托管素材字节 —— 同机静态服务、对象存储、或给你网关加一个上传口。骨架里 ★ 服务适配点 1 就标在这里，未配置时会明确报错。

纯文生视频（seedance:TextVideo）不会碰到这个问题，不需要任何素材托管就能跑通。

你的 4090 能跑什么 —— 决定接的是哪一半活

档位模型能接的活
直接能跑Wan2.1 / TurboWan / FastWan 1.3B（480P）、Wan2.2 TI2V 5B（720P）、LTX-2无声：B-roll、空镜、转场、氛围镜头
需调优Wan2.1 14B（480P）同上，质量更高
单卡别想MiniMax H3（T2VA，带同步音频）官方 SSIM 回归测试硬编码 4 卡

结论：你的 4090 接的是「无声视频」这半条链路。那就不要声明 generateAudio，让 supports() 明确拦住带音频的请求 —— 别让作者以为写了 generate-audio="true" 就真有声。

但你可以两条路同时用

需要「带口型 / 带同期声」的镜头，仍然走 HypiHub 的 Seedance 2.5。两边可以同时配在一个 Profile 里，按 capability 分流：

"bindings": {
  "@hypit/seedance@1#seedance-2-mini": "selfhosted.video",
  "@hypit/seedance@1#seedance-2.5":    "hypihub.default"
}
这是整套机制最漂亮的地方

同一条 SVML 里，model="mini" 的镜头走你自己的卡（零 API 费用），model="2.5" 的镜头走云端（带音频）。作者不需要知道这件事 —— 他写的是能力，Profile 决定谁来兑现。

于是成本结构就变成了：量大面广的无声镜头用自己的算力，少量必须出声的镜头花钱买。这是自部署对接最实际的用法。

7 · 六条硬约束，别踩

约束说明怎么绕
地址必须 HTTPS 或回环 官方 Provider 与示例都强制：https://、http://localhost、http://127.0.0.1 之外一律拒绝。http://192.168.1.x:8000 会被直接拦下 SSH 隧道（见下）、内网域名 + 自签证书、或反代到本地端口
模型目录查询（路径 A） POST /v1/videos 之前必查 GET /v1/models/{model}，且 endpoints 必须含 videos 走路径 B 就没这个要求
端口声明即契约 没在 mapping.fields 里声明的端口，请求一旦使用就在计划阶段失败 这是特性不是缺陷。想让作者少踩坑就声明完整；能力确实没有就别声明
凭据槽是可选的 服务不需要鉴权时，credentials 完全不声明，Profile 里也不配 apiToken —
并发要自己压 骨架默认 concurrency: 1，actionLimits 把 submit / poll / collect 分开限流 单卡串行就跑 1；多卡或队列化服务再往上调
超时是分钟级的 视频生成慢。operationTimeoutMs 官方 Provider 默认 20 分钟，骨架的 requestTimeoutMs 是单次 HTTP 120 秒 长任务把轮询间隔放宽、单次超时设到分钟级；别用默认值硬扛

内网服务的 SSH 隧道方案

最省事的合规做法：把远端服务映射到本机回环，既满足约束又不用配证书。

# 把服务器上的 8188 映射到本机 127.0.0.1:8188
ssh -N -L 8188:127.0.0.1:8188 user@your-server

# 之后 baseUrl 直接写回环地址即可
# "baseUrl": "http://127.0.0.1:8188"

这条最关键

LTX-2.3 是目前唯一单次生成就能出同步音频（含口型）的开源模型。这直接决定了它能接住什么活儿：只有它能在能力上对上 Seedance 的「口播 / 带音」语义 —— 也就是声明 referenceAudio + generateAudio 端口，配合 seedance:ReferenceVideo 用参考音色驱动说话人。

其他几个都是无声模型，只能做 B-roll、空镜、转场。它们能接，但接的是另一半活。选模型之前先想清楚你要做的是哪一类片子。

硬件门槛

显存能跑什么
32GB（RTX 5090）舒适区。LTX-2.3 高分辨率、Wan 2.2 全量、长片段
24GB（RTX 4090 / 3090）可用下限。Wan 2.2 720p、HunyuanVideo 1.5 经量化、LTX-2.3 fp8 720p
16GB 及以下只能重量化 + 低分辨率 + 短片。CogVideoX 类可试，LTX-2 需要 Q3 量化
Apple Silicon 统一内存不推荐 视频模型基本依赖 CUDA；MPS 后端支持不全，且内存带宽与算力都吃紧
对你本机

你现在这台是 M1 Pro / 16GB。跑 Hypit 的本地渲染核心（画面、字幕、动效）完全没问题 —— 那是 Chrome 渲染，不是扩散模型。但跑视频扩散模型不现实。「自己服务器」对这条路线来说是必需品，不是可选项。

成本结构：三条路各自的账

方式计费形态参考量级
HypiHub 托管按次官方示例单条成片 $1.07–$1.15
自购 GPU一次性硬件 + 电费24GB 二手 3090 是社区性价比共识；32GB 5090 是舒适线
租云 GPU 自部署按小时（基础设施费）Modal A100 约 $0.99/小时；RunPod / Lambda / AutoDL 同类

判断逻辑很简单：出片量大、且能跑满 GPU 的时段集中 → 自部署或租卡按小时算，单条成本能压到远低于按次付费。偶尔出片 → 租卡的时间都在等冷启动和调参，反而不划算。

另外提一句：租云 GPU 是基础设施费用，跟「绑定付费 Key 的闭源 SaaS」是两回事 —— 你的工作流、模型、数据都留在自己的环境里，只付电和机时。

9 · 落地步骤

1

先定哪一类片子。要做口播（需要同步音频 + 音色参考）就只能选 LTX-2.3 这一档；做 B-roll / 空镜 / 转场，Wan 2.2 或 HunyuanVideo 就够。

2

把推理服务跑起来并能用 curl 调通。这一步在 Hypit 之外先做完 —— 别把两边的坑叠在一起排查。

fastvideo serve --config your-config.yaml --server.host 127.0.0.1 --server.port 8000

  -H "Content-Type: application/json" \
  -d '{"prompt":"a calm drone shot over misty mountains at dawn","seconds":4,"size":"1280x720"}'

# ComfyUI
curl http://127.0.0.1:8188/system_stats
3

决定复用哪个 capability，然后改骨架的 provider.ts：capability 那一行 + mapping 端口表（只声明真实支持的）。

4

改 start / poll / collect 三处，对齐你服务的真实路径与响应字段。

5

如果没有公网 HTTPS，就搭 SSH 隧道，让服务以 http://127.0.0.1:PORT 出现。

6

构建、安装、配 Profile、体检。

cd packages/provider-selfhosted-video && npm install && npm run build

7

先跑一条最短的片子验证链路。用 seedance:TextVideo + 5 秒 + 720p 这种最小组合，确认提交、轮询、产物落盘都通，再上复杂工作流。

一句话收尾

技术上完全能接，路径也是官方设计好的。真正需要你先想清楚的不是「怎么接」，而是「你要做的片子需不需要同步音频」 —— 这一个问题决定了你得选哪个模型、要不要那张 32GB 的卡，以及整条链路的成本量级。

对你现在这套配置（FastVideo + 4090）来说，答案更明确：无声镜头走自己的卡，出声镜头走云端。两条路配在同一个 Profile 里，SVML 里用 model= 分流，作者完全不用知道。量大的那部分用自己的算力摊平成本，必须出声的那部分才花钱 —— 这是自部署对接最实际的用法。
